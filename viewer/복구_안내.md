# 늘뷰어 복구·유지보수 안내 (다음에 이 프로젝트를 맡는 Claude를 위한 문서)

사용자는 목사님이고 코드를 직접 읽지 않습니다. GitHub에 파일을 **손으로 올리므로**, 작업 결과는 "바꾼 파일만 골라서" 전달해야 합니다.
대화가 새로 시작되면 이전 일을 기억하지 못합니다. 문제가 생기면 이 문서와 `저장키_목록.md`, 프로젝트 문서 `동기화_구조.md`를 먼저 읽으세요.

## 1. 어디에 무엇이 있나
- 저장소: `daniel9ny-glitch/bible` (GitHub Pages), 앱은 `viewer/` 폴더. 새 세션에는 파일이 없으니 `add_repo`로 가져온 뒤 작업합니다.
- `viewer/index.html`: 앱 전체(한 파일, 하나의 IIFE). 구간: CSS → 본문 HTML(다이얼로그들) → 스크립트.
- `viewer/sw.js`: 서비스워커(앱 틀·pdf.js·pdf-lib·`qr/jsqr.min.js` 미리 저장). 미리 저장할 목록(`SHELL`)을 바꾸면 `VERSION`도 올려야 새 목록이 설치됩니다.
- `viewer/qr/jsqr.min.js`: QR 해독 라이브러리(jsQR 1.4.0을 압축한 것).
- `viewer/hwp/`: 늘한글. `convert.js`(한글→PDF 변환), `fonts/`(PDF에 반영되는 글꼴), `studio/`(편집기, 빌드 결과물), `README.md`.
- `viewer/tests/`: 자동 점검. `README.md` 참고. `tests/extra/`는 참고용 추가 시험.
- 사용자 환경: 폴더블(갤럭시), Onyx 전자잉크 태블릿, PC. 실기기 동작은 이 환경에서 확인할 수 없습니다.

## 2. 작업을 시작할 때
1. 저장소를 가져온다. 바꿀 파일은 먼저 복사본을 떠 둔다(`index.before-○○.html`).
2. `cd viewer/tests && npm install` (Playwright는 보통 미리 깔려 있음). 점검:
   - `npm run unit` : 브라우저 없이 계산 함수와 저장 키 문서 일치를 확인 (몇 초)
   - `npm test` : 실제 크롬으로 화면 시험 9개 (몇 분)
3. 고친 뒤에는 위 둘을 모두 돌리고, 바꾼 기능 자체를 확인하는 시험을 따로 만들거나 `tests/extra/`를 참고한다.
4. 사용자에게는 **교체할 파일만** 보낸다. 새 파일(폴더)이 필요하면 어디에 두는지까지 적는다.
5. 새 `neul-` 저장 키를 만들면 `저장키_목록.md`에 적는다. 안 적으면 `npm run unit`이 실패한다. 모든 기기에서 같아야 하는 설정이면 `setSyncKey`에도 넣는다.

## 3. 증상별로 어디부터 볼까
| 증상 | 먼저 볼 곳 |
|---|---|
| 동기화가 멈췄다 / 로그인 만료 알림 | 설정 → 오류 기록. `gRelogin`, `gFriendly`, `gSyncRun`. 로그인 허가는 시간이 지나면 만료되고 앱이 몰래 갱신하지 못함(정상). |
| 한 기기의 수정이 다른 기기에 안 보임 | 동기화는 변경 약 60초 뒤 자동(`gSchedule`→`gAuto`). 더 나중에 저장한 쪽이 이김. `동기화_구조.md`의 "충돌 처리". |
| "(충돌 사본)" 문서가 생김 | 예전 버전 앱이 만든 것. 지금은 만들지 않고 `gDropConflictCopies`가 동기화 때 휴지통으로 보냄. 오래된 버전을 쓰는 기기가 있는지 확인. |
| 큰 PDF가 다른 기기에서 안 열림 | 설정 `neul-gmax`(기본 30MB). 초과분은 열 때 `gFetchBlobLazy`가 받음. |
| 한글 문서를 PDF로 바꿨더니 글자가 사라짐 | `hwp/convert.js`의 글자 위치 변환(`translate … scale(sx,…)`) 처리. 장평≠100% 글자에서 났던 문제를 고친 적 있음. 오래전 저장본은 다시 저장해야 고쳐짐. |
| 글꼴이 다르게 나옴 | PDF에 반영되는 글꼴은 `hwp/fonts/`의 4종(노토산스 KR 계열은 기본 대체, 나눔고딕, 나눔명조, 프리텐다드). 편집기 글꼴 메뉴는 이것만 보이게 고쳐 둠. |
| 잠근 화면이 다시 열면 틀어짐 | `lockRel`, `lockApply`, `applyView`(`viewSnap`). |
| 확대·축소가 버벅임 | `applyLive`, `commitLive`, `miniPing`, 터치 핀치 처리. |
| QR이 안 눌림 | 설정 `neul-qr`('0'이면 꺼짐). `qrScan`, `qrCandidate`(글자만 있는 쪽은 건너뜀), `qrTiles`(작은 QR용 고해상도 조각 훑기). 쪽을 연 직후 몇 초는 읽는 중. |
| 왼쪽 메뉴/위쪽 탭이 기대와 다름 | CSS `@media (max-width:599px), (max-width:860px) and (max-height:559px)`가 위쪽 탭 기준이고, 같은 문자열이 JS(`renderCats`, `matchMedia`)에도 있음. 바꾸면 모두 같이 바꿔야 함. |
| 알림창 모양이 깨짐 | 다시 로그인 알림은 `#gRelogin` CSS. |

## 4. 되돌리기
- 새 버전이 문제를 일으키면 GitHub의 해당 파일 History에서 이전 커밋의 파일을 받아 사용자가 다시 올리도록 안내한다(웹으로 올린 파일은 커밋이 남음). 사용자가 어떻게 올렸는지는 확인 불가이므로 먼저 묻는다.
- 휴지통은 30일(설정값 `neul-clean`) 동안 되살릴 수 있다. 동기화가 지운 문서도 휴지통으로 간다.
- 앱 오류는 설정 → 오류 기록에서 사용자가 복사해 줄 수 있다. 이 기록이 가장 믿을 만한 단서다.

## 5. 지킬 것 (사용자 요청 사항)
- 한국어, 간결하게. 확인하지 못한 것은 추측하지 말고 "확인 불가"라고 쓴다. 칭찬·아첨 없이 솔직하게.
- 충돌 시에는 **더 나중에 저장한 쪽이 남는다.** 사본·충돌 표시를 만들지 않는다(사용자 결정). 동시에 고치면 먼저 저장한 쪽이 사라지는 것이 알려진 대가이다.
- 서재에 넣은 PDF는 크기와 상관없이 드라이브에 모두 올린다. 자동 내려받기 크기 제한은 기기별 설정이다.
- PDF에 반영되지 않는 글꼴은 편집기 글꼴 메뉴에 보이지 않게 한다.
- 작업 결과로 보내는 것은 바꾼 파일뿐. 어떤 파일을 어디에 두는지 한 줄로 적는다.

## 6. 아직 확인하지 못한 것
- 실제 구글 드라이브에서의 대용량(수백 MB) 분할 업로드, 실제 폴더블·폰·Onyx에서의 성능과 화면, 터치 핀치 개선 효과.
- 한글 문서를 한컴오피스에서 열었을 때의 왕복 호환.
- QR: 기기의 바코드 인식(`BarcodeDetector`) 경로(이 환경에서는 쓸 수 없어 시험하지 못함), 실제 주보 PDF의 작은 QR 두 개 중 한 곳이 안 읽히던 원인.
- `innerHTML` 63곳은 코드를 읽어 점검했을 뿐 공격 시도로 시험하지는 않았다.
- 늘한글 편집기(`hwp/studio`)를 다시 빌드하려면 rhwp-studio 원본 소스가 필요한데, 소스는 작업 세션 폴더에만 있었다. 패치 내용: ① 글꼴 목록 함수(`getAllFontSets`)가 빈 목록을 돌려주게 하고 ② 툴바에 반영 글꼴 4종만 보이는 글꼴 메뉴(BUNDLED_FONTS) 추가. 소스가 없으면 upstream에서 받아 같은 패치를 다시 적용해야 한다.
