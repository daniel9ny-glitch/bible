# 늘뷰어 동기화·백업 구조 (2026-10-30 기준)

## 두 장치는 따로 일한다
| | 동기화 | 백업 |
|---|---|---|
| 목적 | 모든 기기를 같은 최신 상태로 | 사람이 볼 수 있는 보관본 |
| 위치 | 드라이브 앱 전용 숨김 폴더(appDataFolder) | 내 드라이브 '늘뷰어 책장' 폴더(분류별 폴더, 파일명=제목.pdf) |
| 방향 | 양방향 | 한 방향(기기 → 드라이브), 새 기기 복원은 수동 |
| 시점 | 변경 약 60초 뒤 자동 + 화면을 닫을 때 + '지금 동기화' 버튼 | 변경 뒤 자동(설정에서 켠 경우, `neul-gbak`) |

## 동기화 대상
- 책 정보(제목·분류·즐겨찾기·북마크·읽은 위치): 항목별 3자 병합. 양쪽이 모두 고치면 북마크는 합치고 나머지는 최근 쪽.
- 필기(획·글상자·메모·사진): 3자 병합. 합치기 전 양쪽을 한 벌 보관.
- 분류 목록, '다른 책'/'남김' 표시, 설정값(저장키_목록.md 1번 표), 받아쓰기 저장본: 병합 또는 키별 최근 값.
- PDF 원본: 서재에 넣은 PDF는 크기와 상관없이 모두 드라이브에 올라간다. 32MB 초과는 8MB씩 나눠 올린다.
- 표지: 작은 표지 파일(nv_c_)을 따로 올려, PDF를 받지 않은 기기도 표지를 본다.
- 한글 문서·노트: 직접 쓴 내용이 PDF(+한글 원본 첨부)에만 있으므로 크기·설정과 상관없이 항상 동기화.

## 다른 기기에서 받을 때
- 자동 내려받기 최대 크기(설정, 기본 30MB, 기기별) 이하 PDF: 자동으로 받는다.
- 초과 PDF: 표지·북마크·필기만 받고, 그 책을 열 때 드라이브에서 받는다(한 번 받으면 유지).

## 충돌 처리 (모든 기기가 같은 결과가 되도록)
- **같은 PDF 원본(특히 한글 문서)을 두 기기에서 고침: 더 나중에 저장한 쪽이 모든 기기에 남는다. 사본·충돌 표시는 만들지 않는다**(사용자 결정, 2026-10-29). 동시에 고치면 먼저 저장한 쪽의 수정은 흔적 없이 사라진다 — 알려진 대가. 다른 기기에서 열기 전에 동기화 버튼을 한 번 누르면 줄어든다.
- 예전 버전이 만든 '제목 (충돌 사본)' 문서(id `…-c<숫자>`)는 동기화 때마다 `gDropConflictCopies`가 휴지통으로 보낸다(30일 안에 되살릴 수 있음). 필기·북마크 등 작업이 더해진 사본은 남긴다.
- 한쪽만 고침: 고친 쪽이 이긴다.
- 지움: 삭제 기록(tombstone)으로 전파. 지운 뒤 다른 기기에서 고쳤으면 되살린다.
- 열어 둔 문서는 동기화가 덮어쓰지 않는다.
- 백업: PDF 내용이 바뀌면 크기가 같아도 다시 올린다(버전 표시).

## 로그인 만료
- 구글 로그인 허가는 시간이 지나면 만료되고 앱이 사용자 몰래 갱신하지 못한다. 만료되면 자동 동기화가 멈추고 서재 화면에 "다시 로그인" 알림(`#gRelogin`)이 뜬다. 누르면 로그인 후 바로 동기화한다.

## 알려진 한계 (확인 불가 포함)
- 실제 구글 드라이브·모바일에서의 대용량(수백 MB) 분할 업로드는 가짜 드라이브로만 시험함 → 실제 동작 확인 불가.
- 필기는 쪽 구성이 바뀐 문서(한글 문서를 다시 저장해 쪽수가 달라진 경우)에서는 병합 대신 최근 쪽을 따른다.
- 이미 올라간 파일은 상한을 낮춰도 지우지 않는다.
- 시계가 크게 어긋난 기기는 '최근' 판단이 틀릴 수 있다.
